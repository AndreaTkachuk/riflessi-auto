## 1. Project in one paragraph

**Riflessi d'Auto** (`riflessi.auto`) is a car portal for the Italian market, similar in spirit to
infocar.ua: a catalog of **new cars** (brand → model → version with specs and list prices),
**side-by-side comparison** of up to 3 versions, and later **used-car listings**, photos and an
**AI assistant** that suggests cars from the catalog. New cars ("novità") are the main focus of the
home page. The project is a portfolio piece today and is designed to be monetized later
(featured listings, dealer subscriptions), so roles/permissions and data model are built with that in mind.

### Critical gotchas

- **NestJS is ESM:** every relative import in `apps/api/src` must end with **`.js`**
  (e.g. `import { X } from './x.service.js'`). Package imports have no extension.
- **Prisma 7 config file is `apps/api/prisma7.config.ts`** (datasource URL from `DATABASE_URL`).
  Generator `prisma-client`, output `apps/api/src/generated/prisma` (gitignored, generated on build/dev).
  The schema still has `moduleFormat = "cjs"` — it works in dev and prod, **leave it**.
  Import client/enums from `../generated/prisma/client.js`.
- Prisma-side defaults: `@default(cuid())` and `@updatedAt` are filled by Prisma, **not** by the DB.
  Raw SQL inserts must provide `id`, `createdAt`, `updatedAt` manually.
- New native deps need `pnpm approve-builds` (pnpm 12 blocks build scripts; approvals live in `pnpm-workspace.yaml`).
- Nest 12 CLI generated `ObserveModule` (`@nestjs/observe`) — it was **removed** on purpose. Don't re-add.
- **`@riflessi/shared` is consumed from `dist/`** — it must be built first. Root `pnpm dev*` scripts and the
  `build` scripts of api/web do it automatically. While `pnpm dev` runs, `tsc --watch` rebuilds shared, but
  `nest start --watch` does **not** restart on shared changes — restart `dev:api` after editing shared.
- Don't overwrite generator config files wholesale (e.g. `next.config.ts`) without reading them first.
- Two separate databases: **local** (Podman) and **prod** (Neon). Data does not sync.

## 6. Architecture & conventions

### Request flow

Browser → **Next.js** (Vercel) → rewrite `/api/*` → **NestJS** (Cloud Run) → Prisma → Postgres (Neon).
Same-origin for the browser, so the auth cookie works without CORS.
Server components call the API directly with `process.env.API_URL` via **`serverFetch<T>(path, { auth? })`**
(`lib/server-api.ts`). **Never write raw `fetch` to the API in server components.**
- Public endpoints: `serverFetch('/api/brands')` — no cookie, no `cookies()` call.
- Login-only endpoints (`/api/auth/me`, `/api/admin/...`): `{ auth: true }` → forwards the cookie,
  and **skips the request entirely when there is no cookie** (no useless 401 round-trips).
- `getCurrentUser()` is wrapped in React `cache()`: layout + page in one request = one `/auth/me` call.
- Avoid unnecessary requests in general: fetch in parallel with `Promise.all`, don't refetch what the layout already has.

### Backend (NestJS)

- Global prefix `/api`. One feature = one module (`auth`, `catalog`, later `listings`, `media`, `ai`).
- Controllers = HTTP only; services = logic; DTOs validated by global `ValidationPipe`
  (`whitelist`, `forbidNonWhitelisted`, `transform`).
- **Security is "closed by default":** global `AuthGuard` (`APP_GUARD`) requires login everywhere.
  - `@Public()` → open route (guard still attaches `req.user` if a valid cookie is present).
  - `@Roles('ADMIN', 'EDITOR')` → role check (403). Role is read **from the DB**, not from the token.
  - `@CurrentUser()` → injects `req.user` (`PublicUser`, never includes `passwordHash`).
- Public catalog routes are addressed by **slug**; admin routes live under **`/api/admin/...`** and use **id**.
- Admin controllers are separate classes with `@Roles` on the class.
- `PrismaExceptionFilter`: P2002 → 409, P2003 → 409, P2025 → 404, messages in Italian.
- Slugs: generated with `slugify(name)` **only on create**; never auto-changed on rename (SEO).
- Errors thrown with Nest exceptions (`NotFoundException('Marca non trovata')`), Italian messages.

### Auth

- `POST /api/auth/register`, `POST /api/auth/login` (200), `POST /api/auth/logout` (204), `GET /api/auth/me`.
- JWT payload `{ sub, role }`, expires 7d, cookie `access_token`: httpOnly, SameSite=Lax, Secure in production, path `/`.
- Passwords: argon2. Login error message is identical for unknown email / wrong password.
- Make a user admin: local `prisma db execute`; prod Neon SQL Editor:
  `UPDATE "User" SET role = 'ADMIN' WHERE email = '...';`

### Shared types (`packages/shared`)

- Holds the **API contract**: enums (as `const` objects + types), response shapes **as JSON** (dates = ISO
  strings, Decimal = string), `slugify`. Web imports types only from `@riflessi/shared` — never Prisma types.
- Not in shared: UI labels (stay in `web/lib/labels.ts`, typed `Record<Enum, string>`), DTO classes, Prisma.
- New Prisma enum ⇒ add it to `shared/src/enums.ts` **and** to `api/src/common/shared-enums.check.ts`.
- New API response used by web ⇒ add its interface to `shared/src/*.ts`.
- Relative imports inside shared also end with `.js` (ESM, nodenext).

### Frontend (Next.js)

- Server components by default; `'use client'` only for interactivity.
- **Admin page pattern:** `page.tsx` (server) fetches data → passes props to a client `*-manager.tsx`
  (table, search, delete) + `*-form.tsx` (create/edit, one form for both modes). After a mutation:
  `router.refresh()` (no duplicated client state). Forms use React 19 **`useActionState`**.
  Give the form a `key` (id or `'new'`) so switching records remounts it.
- API errors shown via `readApiError(res)` (handles Nest `message: string | string[]`).
- `admin/layout.tsx` redirects non-logged users to `/login?next=/admin` and non ADMIN/EDITOR to `/`.
  This is UX only — **real protection is the NestJS guard.**
- `/login` uses `safeNext()` to prevent open redirects.

## 9. CI and deployment

### CI — `.github/workflows/ci.yml`

- Runs on every pull request and on push to `main`. Two parallel jobs (their names are the required
  status checks in branch protection — don't rename without updating the rule):
  - **`api`**: install → build (shared + prisma generate + nest) → lint → typecheck → unit tests.
  - **`web`**: install → lint → build (shared + next build, includes type checking).
- Dummy env in CI: `DATABASE_URL` (prisma generate only), `API_URL` (rewrites only).
- Before pushing, run locally what CI runs: `pnpm build && pnpm lint && pnpm typecheck && pnpm test` (api),
  `pnpm lint && pnpm build` (web).

### Deployment (automatic on push/merge to `main`)

### Frontend — Vercel

- Root Directory `apps/web`. Env: `API_URL=https://riflessi-api-<id>.europe-west1.run.app` (no trailing slash,
  no `/api`), `ENABLE_EXPERIMENTAL_COREPACK=1`.

  (runs inside `apps/web`; don't prefix paths with `apps/web`).
- Hobby plan = non-commercial only; switch to Pro before monetizing.

### Backend — Google Cloud Run (via GitHub Actions)

- Workflow `.github/workflows/deploy-api.yml`, triggers on `apps/api/**`, `packages/**`, `pnpm-lock.yaml`, the workflow file.
- Dockerfile copies `packages/shared`; `pnpm --filter @riflessi/api build` builds shared first.

  push to Artifact Registry repo `riflessi` (cleanup policy keeps 3 images) → `gcloud run deploy riflessi-api`.

  Secret: `NEON_DIRECT_URL`.
- New env var for the API ⇒ add secret in Secret Manager + grant `secretAccessor` to runtime SA +
  extend `--set-secrets` in the workflow **before** pushing code that requires it.

### Database — Neon
